# Integration Patterns

How `.meta.ts` files plug into the rest of the toolchain — agent runtimes, Figma MCP, build pipelines, CI, Storybook.

---

## With an agent runtime

Agents follow a two-step lookup: scan the index first (cheap), then read the relevant `.meta.ts` files (depth on demand).

```ts
import type { ComponentMeta } from "@/meta.types";

const index = await readJSON<IndexEntry[]>("metadata/index.json");

const candidates = index.filter((c) =>
  c.keywords.some((k) => prompt.toLowerCase().includes(k)) || c.priority === "high",
);

for (const c of candidates) {
  const { meta }: { meta: ComponentMeta } = await import(c.path);

  // Pick a variant via aiHints.selectionCriteria
  // Honor relationships.mustBeChildOf / mustBeParentOf
  // Reject cells listed in variants.invalidCombinations
}
```

The index is generated by `agentic-design-systems` Step 8. The contents of each `.meta.ts` are what this skill produces.

## With Figma MCP

Figma supplies visual context (layout, color values, typography); `ComponentMeta` supplies behavioral and structural context (when to pick which variant, what to nest inside what).

```ts
// 1. Pull design context for a Figma node
const figmaCtx = await Figma.get_design_context(nodeId);

// 2. Resolve to a component via metadata
const { meta } = await import(
  `@/components/${figmaCtx.componentName}/${figmaCtx.componentName}.meta`
);

// 3. Pick variant from selectionCriteria, honor relationships
const variant = meta.aiHints.selectionCriteria[figmaCtx.intent];
```

To wire Figma → metadata, populate `component.figma.nodeId` in each `.meta.ts`. The template leaves it as `nodeId: null`; fill it in when the Figma node stabilizes.

## With code generation

Agents generating UI should prefer existing components over raw markup:

```tsx
// ❌ inventing markup
<div style={{ background: "green", padding: 8 }}>Active</div>

// ✅ resolving via Chip.meta.ts
//    selectionCriteria["status indicator"] → "appearance: 'success'"
<Chip appearance="success">Active</Chip>
```

For multi-component compositions, emit `aiHints.usage.commonPatterns[].composition` verbatim, swapping in labels:

```ts
// Button.meta.ts → commonPatterns[0]
{
  name: "submit-cancel pair",
  composition: '<Stack ...><Button appearance="primary">Submit</Button>...</Stack>',
}
```

## With CI

Run the validator (`agentic-design-systems` Step 9) and the index builder (Step 8) on every metadata change:

```jsonc
// package.json
{
  "scripts": {
    "validate:metadata": "tsx scripts/validate-metadata.ts",
    "build:index": "tsx scripts/build-index.ts"
  }
}
```

Both should run in CI. The validator fails the build on incomplete metadata; the index builder guarantees the JSON index reflects what's actually on disk.

## With Storybook

Co-locate stories with `.meta.ts` files; one story per variant matrix cell makes design-space regressions obvious.

```
Button/
  Button.tsx
  Button.meta.ts          ← produced by this skill
  Button.tokens.css       ← component-scoped tokens referenced by meta.tokens
  Button.stories.tsx      ← one story per appearance × size cell
  Button.test.tsx
  index.ts
```

`Button.meta.ts` and `Button.stories.tsx` are independent artifacts but must stay in sync — if you add an axis value, add a story for it. The `commonPatterns` snapshot test described in [TESTING.md](TESTING.md) helps catch drift.

## A note on framework choice

This skill is framework-agnostic: `ComponentMeta` doesn't encode React-isms. The template happens to use React types (`ReactNode`, `MouseEvent`) because that's the rss-feed-v0 stack — swap them for your framework's equivalents and the rest of the schema still applies. Don't add a `framework` field; it's noise.
