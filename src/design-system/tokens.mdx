# Design Tokens

This project uses a **two-tier color token architecture** with strict Tailwind
exposure. Decisions and ambiguities live in
[ADR-0003](https://github.com/davidinoa/rss-feed-v0/blob/main/docs/adr/0003-tiered-color-tokens.md)
(architecture) and
[ADR-0004](https://github.com/davidinoa/rss-feed-v0/blob/main/docs/adr/0004-adopt-quiet-reading-room.md)
(Quiet Reading Room visual direction). For the visual spec — palette values,
component design intent — see
[DESIGN.md](https://github.com/davidinoa/rss-feed-v0/blob/main/DESIGN.md) at
the repo root.

## Tier 1 — Primitives (private)

Raw palette values, named descriptively by appearance: `--warm-parchment`,
`--burnt-amber`, `--ink-espresso`. They're defined as CSS variables on `:root`
but are **not** exposed as Tailwind utilities — `bg-warm-parchment` is not a
valid class. Browse the full palette in the **Colors → Primitives** story.

## Tier 2 — Semantics (public)

Intent-bearing aliases named by role: `--primary`, `--background`,
`--muted-foreground`. Each semantic references a primitive via `var(...)` and
is exposed through `@theme inline` as a Tailwind utility (`bg-primary`,
`text-foreground`). Browse them in the **Colors → Semantic** story — each
row shows the primitive referenced in light and dark mode, the matching
utility, and usage guidance.

## Strict mode

Tailwind v4's default color palette is disabled (`--color-*: initial`).
`bg-blue-500`, `text-gray-700`, and similar are **not valid utilities** in
this codebase. Reach for the semantic token instead. The functional
non-palette values `transparent`, `currentColor`, and `inherit` are preserved.

## States are implicit

Hover, active, and focus colors are expressed via Tailwind's opacity modifier
(`hover:bg-primary/90`), not explicit state tokens. This is intentional — it
keeps every `npx shadcn add` install drop-in compatible. See ADR-0003 for the
"if specs ever diverge from a simple opacity overlay, promote affected states
one at a time" rule.

## Visual reference

For the canonical palette values, type scale, component design intent, and the
naming rationale behind each primitive (Warm Parchment, Burnt Amber, Ink
Espresso, etc.), see
[DESIGN.md](https://github.com/davidinoa/rss-feed-v0/blob/main/DESIGN.md) at
the repo root. The **Colors → Semantic** story renders the live values and
their primitive mapping in one place; DESIGN.md §2 is the prose spec.

## What's NOT tokenized

Typography (beyond `--font-sans` / `--font-serif`), spacing, motion, elevation,
and z-index intentionally use Tailwind defaults. They aren't formalized as
project tokens because Tailwind's defaults already serve the brand and no
current consumer demands a custom value. See ADR-0003 for the rationale and
re-evaluation criteria.
